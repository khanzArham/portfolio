## Brief

Online shops get a steady stream of "where is my order?" messages. This app lets customers answer that themselves: they sign in and see their order move through **Placed**, **Processing**, **Dispatched** and **Delivered** as it happens.

## Method

- **React** for the front end.
- **Firebase Authentication** with Google Sign-In, so customers sign in without a new password.
- **Cloud Firestore** for order data, with real-time listeners so a status change appears without a refresh.
- **Firestore security rules** that isolate data, so each customer can read only their own orders.

I chose Firebase as a serverless back end: live sync and authentication out of the box, and no servers to run.

## Failure Log

### Real-time listeners used up the Firestore read quota

**What happened:** during testing, the app used up Firestore's read quota far faster than its traffic could explain.

**Why:** the real-time `onSnapshot` listeners were attached in parent components and never detached when those components unmounted. Re-renders kept adding new listeners, and every one of them counted reads.

**What I changed:** I moved each listener into a custom React hook that returns a cleanup function, so the listener is removed when the component unmounts, and I flattened the component state to cut unnecessary re-renders.

## Outcome

The app tracks orders live for signed-in customers. The quota problem taught me how to manage real-time listeners in React: attach them in one place, always clean them up, and watch hook dependencies closely.
